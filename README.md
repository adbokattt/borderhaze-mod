# Border Haze

Fabric-мод для Minecraft Java Edition 26.2: заменяет ванильную визуализацию границы мира
эффектом размытия и «ряби» за её пределами. Размер, центр и скорость границы по-прежнему
управляются командой `/worldborder`.

**Статус:** BorderHaze (граница) + GLITCH (этап 3d: силуэт Стива с рваным колеблющимся краем, гладкие фиолетово-синие и голубые каймы, глаза).

## Требования
- Minecraft Java 26.2
- Fabric Loader 0.19.3+
- Fabric API 0.156.0+26.2 (или новее для 26.2)
- Java 25 (идёт в комплекте с официальным лаунчером)

## Сборка
Сборка выполняется автоматически в GitHub Actions (вкладка **Actions** → последний запуск →
**Artifacts** → `borderhaze-jar`).

Локально: установите JDK 25 и Gradle 9.5.1, затем `gradle build`. Jar появится в `build/libs/`.

## Структура
- `src/main` — общий код (клиент + сервер)
- `src/client` — только клиентский код (рендер)

## Для администраторов серверов (Fabric, 26.2)

Положите тот же jar и Fabric API в папку `mods` сервера. Игрокам без мода ничего не отправляется (они видят обычную границу).

- Команда `/borderhaze ...` требует права 2+ (оператор, командный блок, функция датапака, консоль). Обычные игроки её не видят.
- Каждое изменение сохраняется в `config/borderhaze-server.properties` и сразу уходит всем онлайн-игрокам с модом; вошедшие позже получают настройки при входе.
- `/borderhaze off` возвращает всем ванильную границу, `/borderhaze on` включает эффект обратно.
- Локальные настройки игрока (`/bhlocal`, `config/borderhaze.properties`) действуют только вне серверов с Border Haze. Игрок может отказаться от серверных настроек: `ignoreServerSettings=true`.


## Структура проекта (для будущих механик)

Один мод, независимые механики, общая инфраструктура:

```
dev.borderhaze
├─ core/      общее: AdminPermission (единственное место, где определено, кто администратор)
├─ settings/, server/, network/   BorderHaze: серверные настройки, команда /borderhaze, синхронизация
├─ glitch/    GLITCH (общая часть): состояние, хранение, команды /glitch, сеть, события, API, хук Vanish
├─ client/…   клиентская часть: border (рендер границы), glitch (приём состояния), config, command (/bhlocal)
```
Правила: механики не импортируют друг друга, делятся только `core` и общей инфраструктурой (права, сеть, события жизненного цикла, файлы). Новая механика = новый пакет + одна строка инициализации в `BorderHaze.onInitialize` и в `BorderHazeClient`.

## GLITCH

- Команды (только администраторы, права 2+, работают из командных блоков и функций): `/glitch on|off|toggle|status [игрок]`.
- Состояние хранится по UUID игрока в `<мир>/borderhaze/glitch.json`; переживает смерть, респавн, перезаход и перезапуск сервера.
- Любое изменение сразу отправляется всем клиентам с модом; вошедшие позже получают состояние при входе.
- Приоритет над Vanish: пока GLITCH активен, игрок отслеживается и виден всем (встроенный хук для Vanish в стиле наблюдателя); для других Vanish-систем см. `GlitchApi.forcesVisibility(player)` и событие `GlitchEvents.CHANGED`.

### GLITCH: внешность (этап 2)
Игрок, у которого включён GLITCH, рисуется на клиентах с модом как полностью чёрный силуэт со светящимися глазами: без брони, плаща, элитр, предметов в руках, второго слоя скина и ника. Анимации обычного игрока сохраняются (модель та же). Настоящий скин аккаунта, инвентарь и механики не меняются. В первом лице руки тоже чёрные. Эффекты искажения (RGB-смещения, мерцание, призрачные копии) будут на этапе 3.

### GLITCH: оболочка (этап 3a)
Тело — обычная модель игрока в «маркерном чёрном» (чёрная на вид, с едва заметным синим значением). Постэффект находит эти пиксели на готовой картинке и строит фигуру: рваный дрожащий контур, фиолетовая/синяя/голубая кайма, призрачные копии, смещённые полосы, помехи. Два белых глаза рисуются эффектом вокруг проецируемых 3D-позиций (ядро и свечение), а не на скине; за стенами они скрыты. Раз в доли секунды отдельная часть тела или вся фигура ненадолго исчезает. Общая инфраструктура рендера лежит в `client/core` (UniformBinder), её используют обе механики.

### GLITCH: отладка
`/glitchlocal debug true` показывает, что эффект считает телом GLITCH (пурпурным) и область подсказки (голубая): так видно, находит ли он модель игрока.
